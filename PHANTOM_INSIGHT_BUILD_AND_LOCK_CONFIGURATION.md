# PHANTOM INSIGHT — BUILD & LOCK CONFIGURATION

Status: LOCKED
Priority: P0

## Purpose
Define the authoritative build contract for Phantom Insight. This configuration is inherited by every future Phantom repository, runtime, worker system, and deployment environment unless an explicit, recorded exception is approved.

## Build Principle
Phantom Insight is built as a production product on the Phantom Motherboard. Build work is outcome-driven: BUILD → ADDRESS → CORRECT → UPGRADE → VERIFY → INTEGRATE → DEPLOY → OBSERVE → REPEAT.

## Required Build Gates
1. Constitution and Master Canon compatibility
2. Product Canon traceability
3. Motherboard contract compatibility
4. Security and privacy validation
5. Data-model and migration validation
6. Accessibility validation
7. Functional and integration testing
8. AI quality/safety evaluation where applicable
9. Billing and entitlement validation where applicable
10. Performance and reliability validation
11. Artifact integrity and provenance
12. Staging verification
13. Production deployment readiness
14. Rollback/recovery readiness

## Workforce
- Mastermind orchestrates and prioritizes.
- Big Daddy Workers own outcomes and correct discovered defects.
- Big Daddy Motherboard Specialist protects foundational architecture.
- Big Daddy Librarian protects canonical state, provenance, and institutional memory.
- Big Daddy Infrastructure Provisioner provisions and verifies infrastructure.
- Launch & Deployment Engineer owns release execution.
- Phantom Producer controls production promotion.
- SNITCH independently verifies worker claims and production results.

## Repository Inheritance
Every future Phantom repository must consume the current authoritative configuration baseline and register its implementation against the Mastermind configuration. Foundational drift is prohibited without documented architectural review.

## Completion Rule
A build is NOT complete because source code exists or a local build succeeds. Completion requires machine-verifiable evidence for the applicable gates and, for launch work, successful live production verification.

## Production Boundary
GitHub is a source/configuration repository only and is not Phantom's runtime or production authority. Replit and Vercel are excluded from Phantom production architecture. Third-party infrastructure may only operate as an explicitly controlled external substrate behind the Phantom External Boundary and may not become Phantom's authority.

## Customer Launch Definition
Insight is considered launched only when the live customer journey is verified end-to-end: public access → onboarding → PHIA/experience → persistence → entitlements → applicable billing → return journey → monitoring.

## Lock
This file is part of the Mastermind configuration baseline. Any future repository or product implementation must inherit these rules. Foundational changes require explicit architectural review and a Decision Log entry.
