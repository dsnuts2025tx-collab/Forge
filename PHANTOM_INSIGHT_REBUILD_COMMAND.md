# PHANTOM INSIGHT — CLEAN-ROOM REBUILD COMMAND

**Status: LOCKED / ACTIVE BUILD DIRECTIVE**

## Mission

Retire the legacy Phantom Insight implementation as a product foundation and rebuild Phantom Insight from a clean, first-party-controlled foundation using the Phantom Family workforce and Forge as the engineering factory.

The objective is not to preserve legacy complexity. The objective is to deliver a smaller, cleaner, stronger, customer-facing product that can launch, serve real users, and generate legitimate revenue.

## Ownership principle

Phantom Insight core must be Phantom-controlled.

Do not introduce third-party services as foundational dependencies merely for convenience. External services may exist only at an unavoidable boundary (for example lawful payment rails, app stores, or regulated networks) and must remain replaceable, isolated, documented, and governed by Phantom's External Boundary Layer.

Do not make Vercel, Cloudflare, OpenRouter, third-party analytics, third-party CMS platforms, or similar vendors foundational to Phantom Insight merely because they are available elsewhere. Select the actual production infrastructure deliberately from Phantom-controlled resources.

## Family operating mode

All authorized workers operate in full overdrive:

BUILD → ADDRESS → CORRECT → UPGRADE → VERIFY → ESCALATE → REPEAT

Every worker owns outcomes in its territory. Finding a problem is not completion. Workers must resolve problems within authority, coordinate dependencies, verify changes, and surface anything requiring higher-level approval.

## Required control-plane foundations

The rebuild must explicitly define and implement:

- canonical identity and object IDs
- configuration and feature flags
- event spine
- data classification and lifecycle
- knowledge provenance
- AI model/prompt/version registry
- AI evaluation and regression framework
- audit trail
- dependency registry
- secrets/key management
- observability
- staged release/rollback
- backup and restore
- disaster recovery
- security/supply-chain checks
- revenue and entitlement ledger

## Product-first launch target

The first release must be a complete customer journey, not a collection of unfinished features:

DISCOVER → ENTER → ONBOARD → MEET PHIA → EXPERIENCE → PERSONALIZE → UPGRADE → PAY → RECEIVE ENTITLEMENT → RETURN

The team may defer deep-universe expansion until the core loop is excellent.

## Realm rule

Realms are built as extensible first-party product modules. Each realm must have an identity, purpose, educational/experiential contract, content provenance, accessibility requirements, progression rules, analytics events, QA criteria, and upgrade path.

## Data rule

Customer data belongs to the Phantom product domain. Minimize collection, classify every data type, define retention/deletion/export rules, and never create unnecessary vendor copies of customer data.

## AI rule

PHIA must remain transparent: symbolic/reflective experiences must not be represented as verified supernatural powers. AI behavior must be evaluated for factuality, safety, cultural respect, privacy, consistency, and regression.

## Release rule

No "done" claim without evidence. Production readiness requires appropriate automated tests, security review, deployment verification, customer-path smoke testing, payment/entitlement testing where applicable, observability, rollback capability, and documented evidence.

## Improvement rule

While rebuilding, workers must inspect adjacent architecture for missing pieces, misplaced responsibilities, unnecessary dependencies, technical debt, security weaknesses, UX friction, performance problems, educational weaknesses, and revenue leaks. Legitimate improvements should be incorporated when they pass the applicable governance gates.

## Legacy rule

Legacy Phantom Insight assets are reference material only. Do not blindly migrate old dependencies, architecture, data models, UI, or code. Preserve useful intellectual/product decisions; discard accidental complexity.

## Success condition

Phantom Insight is successful when a real customer can discover it, use it, understand its value, purchase an offering through the lawful payment boundary, receive the promised experience, and return to a reliable product — with measurable evidence of every critical step.
