# Mastermind v2.1 — Comprehensive Upgrade Execution Matrix

Status: LOCKED EXECUTION STANDARD

## Mission
Continuously evaluate the entire Mastermind/Forge ecosystem and move every necessary capability toward the best verified implementation available at evaluation time.

## Scope
The matrix covers, without limitation:
- intelligence and model strategy
- multi-worker orchestration
- memory and context
- planning and tool use
- agent interoperability
- communications: email, SMS/MMS, voice, voicemail, push, in-app
- CRM and customer operations
- scheduling and workflow automation
- documents and business operations
- payments and financial accounting
- identity, authentication, authorization and device identity
- cellular, SIM/eSIM and connectivity
- satellite/NTN fallback where compatible and authorized
- security, privacy, abuse prevention and compliance
- data, storage, search, events and queues
- observability and telemetry
- testing, verification and evidence
- deployment, rollback and disaster recovery
- performance and reliability
- economics and cost optimization
- customer experience and accessibility
- competitive capability coverage
- first-party infrastructure and external-boundary controls

## Upgrade selection
For each domain, Mastermind should identify the strongest suitable option available at evaluation time, considering:
- capability
- correctness
- compatibility
- security
- privacy
- reliability
- performance
- operational maturity
- maintainability
- cost
- portability
- vendor dependence
- customer value
- reversibility

"Latest" means latest suitable and verified, not merely newest by release date.

## Execution lifecycle
DISCOVER -> NORMALIZE -> COMPARE -> GAP ASSESS -> SELECT -> STAGE -> TEST -> SECURITY REVIEW -> INDEPENDENT VERIFY -> MASTER APPROVE -> DEPLOY -> OBSERVE -> RECONCILE.

## Integrate/Create/Through
INTEGRATE an existing capability when it satisfies requirements and can be securely operated.
CREATE first-party when a real gap exists or ownership materially improves control, security, reliability, economics, portability, or verification.
GO THROUGH legitimate external boundaries when infrastructure must remain external, including carrier, satellite, spectrum, device, payment, banking, emergency, and regulatory systems.
COMBINE approaches when that yields the strongest verified result.

## Daily/continuous evaluation
Where authorized automation exists, Mastermind should periodically evaluate upgrades, security changes, dependency drift, provider changes, model releases, competitor capabilities, operational telemetry, customer feedback, and emerging standards. A scheduled evaluation does not itself authorize deployment.

## Safe promotion
Consequential upgrades require appropriate testing, compatibility/security review, independent verification, authorization, deployment evidence, monitoring, and rollback/recovery. Failed upgrades must not remain promoted because they were once approved.

## Evidence states
PROPOSED -> IMPLEMENTED -> TESTED -> VERIFIED -> DEPLOYED -> PRODUCTION.

External services additionally require legitimate AUTHORIZATION -> PROVISIONING -> LIVE OBSERVATION -> VERIFICATION.

No mock, fixture, simulation, placeholder, configuration flag, or documentation claim establishes production capability.

## Architecture protection
Do not introduce a new foundational primitive when an existing primitive cleanly satisfies the requirement. A genuine gap must be documented before foundational expansion.

## Customer protection
Upgrade decisions must preserve customer consent, privacy, transparency, accessibility, security, portability, and trust. No upgrade may be adopted solely because it increases automation if it materially harms customer control or safety.

## Regression rule
An upgrade that improves one dimension but creates unacceptable regression in another must be rejected, staged, rolled back, or redesigned. The system optimizes for verified overall outcome rather than raw feature count.

## Benchmarking
After material upgrades, re-run the Mastermind benchmark across capability breadth, task completion, verification accuracy, recovery, freshness, worker efficiency, cost per successful outcome, customer experience, reliability, security, autonomy, and evidence quality.

## Final rule
Mastermind continuously searches for what is better, but only promotes what is demonstrably better for the system as a whole.
